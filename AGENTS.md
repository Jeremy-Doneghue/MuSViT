# Session continuity

Read `PROJECT_DIARY.md` before starting work. It contains the current objective,
verified state, proposed next steps, and dated session entries. Follow its links
for subsystem details rather than treating generated output folders as documentation.

After meaningful work, update the current-state/next-step sections if needed and
append a dated entry recording changes, decisions, checks and results, remaining
limitations, and the exact next action. Distinguish proposals from agreed decisions
and code inspection from executed experiments. Do not invent historical results.
Keep older entries intact, except to correct factual errors explicitly.

Preserve existing uncommitted work. Keep generated datasets, scans, annotations,
credentials, and model weights out of documentation and commits; record paths,
seeds, configurations, and summary results instead. Never overwrite an existing
dataset export to make a new experiment.
